# MauLamour

> A dating website where people fill in a detailed profile, find matches and chat with them.

## Start here
Open [`.claude/CLAUDE.md`](.claude/CLAUDE.md) and fill in the **Configuration** table (name, people, dates, board, Agile method, tools, limits). Then open [`.claude/work/TASKLIST.md`](.claude/work/TASKLIST.md) and work down the list.

## The files
All project documents are in the `.claude/` folder, so the root stays clean.

| File | What goes in it |
|---|---|
| [`CLAUDE.md`](.claude/CLAUDE.md) | **Configuration** (name, people, dates, board, Agile method, tools, limits) and the rules for working here (including what to ask before doing, and how the app's data is kept), for people and AI assistants. |
| [`agile/AGILE.md`](.claude/agile/AGILE.md) | What applies to every Agile method: vision, roadmap, release planning, estimation, anti-patterns. |
| [`agile/methods/`](.claude/agile/methods/README.md) | How each Agile method works (Scrum, Kanban, Scrumban, XP, Lean, FDD). The project follows the one named in `CLAUDE.md`. |
| [`work/TASKLIST.md`](.claude/work/TASKLIST.md) | **Still to do**: dates, sprint plan, the open work, and every step from idea to release. Tick things off as you go. |
| [`STUDY.md`](.claude/STUDY.md) | **Why**: the problem, who it is for, typical users, similar products, goals, risks. |
| [`work/REQUIREMENTS.md`](.claude/work/REQUIREMENTS.md) | **What**: the list of features (FR) and qualities (NFR), and nothing else. |
| [`work/USE-CASES.md`](.claude/work/USE-CASES.md) | **Who does what**: the users, use cases step by step, and a table of who can do what. |
| [`work/USER-STORIES.md`](.claude/work/USER-STORIES.md) | **What each user wants**, as stories with checks. Always the same as the task board. |
| [`NAMING.md`](.claude/NAMING.md) | How to name methods, variables and files, with real before/after examples. |
| [`BRAND.md`](.claude/BRAND.md) | **Look**: name, tone, colours, fonts, logo, how to write messages. |
| [`DECISIONS.md`](.claude/DECISIONS.md) | Choices already made, and why. |
| [`MEETINGS.md`](.claude/MEETINGS.md) | What was agreed in each meeting, and who does what next. |
| [`work/IDEAS.md`](.claude/work/IDEAS.md) | A notepad for any idea, even ones that may never be built. |
| [`TESTING.md`](.claude/TESTING.md) | Test plan, which test checks each feature, and the test log. |
| [`CHANGELOG.md`](.claude/CHANGELOG.md) | What changed in each version. |
| [`work/DONE/`](.claude/work/DONE/) | What was done and why, with the date. One file per work session; the rules are in `CLAUDE.md`. |
| [`AGENTS.md`](AGENTS.md) (root) | Points Codex to `CLAUDE.md`. |

## The main rule
**Write each thing in one place only.** Rules go in `CLAUDE.md`, requirements in `work/REQUIREMENTS.md`, unfinished work in `work/TASKLIST.md`, and finished work in `work/DONE/`. If something is written in two places, one copy will end up wrong. If it is only said in a chat, it will be forgotten.
